### 2026-09-27 · Rotating a phone to landscape turns off the desk-only authority gate
- **Severity:** medium (mock data, but it defeats the showcase's own "no approve authority on the phone" rule) · **Status:** FIXED on branch `fix/mobile-companion` (owner-directed pass, 2026-09-30); still live in production until that branch is merged to `main` · **Visible:** yes, on any phone wider than 720px in landscape
- **Fix:** `src/surface.js` is the one source of the breakpoint (companion < 1024px, workstation ≥ 1024px). `src/hooks/useSurface.js` stamps `data-surface` / `data-tier` / `data-shape` / `data-authority` on `<html>`; the CSS reads only those attributes (`src/surface.test.mjs` fails if any stylesheet declares a width breakpoint below 1024px). Desk authority is scoped by device tier (`resolveSurface().deskAuthority`): no phone gets it in either orientation, nor does the full desktop view forced on a phone. DECISIONS.md ADR-001.
- **Evidence:** `e2e/mobile-authority.spec.js` gap band (844×390, 932×430, 768×1024, 1000×760) and in-place rotation 390×844 → 844×390 — 9 failing at baseline, all passing after (Approve/Reject count asserted 0). `scripts/mobile-sweep.mjs` authority matrix: 42 failing at baseline → 0 (7 desk-only routes × 750/844/932 landscape, 768/834 portrait tablets, a 1000px window, plus the forced desktop on a phone). `src/surface.test.mjs` walks every width 721–1023 and asserts companion + no authority.
- **Evidence:** `useIsMobile()` (`src/app.jsx:106`) is `matchMedia("(max-width: 720px)")` with no orientation or pointer signal, and `routeScreen` gates `DESK_ONLY_VIEWS` on it. The repo's own sweep widths for phones in landscape are 667, 844 and 932px (`scripts/viewport-sweep.mjs`). Only 667 stays gated. At 844 and 932 the desktop shell renders, including live Approve/Reject on write-backs, as confirmed by `media/benchmark/results.json` (phone-landscape: no bottom bar, desktop side rail). The same 720 is typed separately in `src/index.css` (493, 524, 1858, 2037) with no shared constant.
- **Test gap:** `e2e/mobile-authority.spec.js` only uses 375×812. `scripts/mobile-sweep.mjs` runs 844×390 but checks layout, never the gate.
- **Fix (owner-approved plan, `portofolio-hub/docs/MOBILE_COMPANION_BENCHMARK.md` Ops item 1):** one breakpoint shared by the JS and the CSS, authority that does not change on rotation, and a landscape case in the authority test.
- **Note:** this finding is the subject of the Oct 1 MIMIR² & Ogham walkthrough (found by two recorded agent sessions on 2026-09-27). Do not fix it before that video is published.

### 2026-09-30 · Report format badge "csv" is unreadable (ink on ink) on every surface
- **Severity:** low · **Status:** open (found in passing during the mobile pass; not on its list) · **Visible:** yes, Reports, every report card whose format is csv, every width
- **Evidence:** `.role-head .mono { color: var(--ink) }` matches the `<Pill tone="ink" mono>` in `src/screens/reports.jsx:114` and beats `.pill-ink { color: var(--paper) }` on specificity, so the text is drawn in `--ink` on an `--ink` fill (computed color = background = `oklch(0.16 0.015 250)`).
- **Fix direction:** scope the `.role-head .mono` rule to non-pill text, or raise `.pill-ink`'s colour rule; a one-line CSS change, but outside this pass.
